# TRL Contacts

A small team web app for tracking home builders: their people, title companies
and escrow teams, concession rules, special processes, CC rules, and Dropbox
links, plus a general contact list. Built for a mortgage loan processing team.

Live app: https://truratelending.github.io/trl-contacts/

## How it works

- **This repo is just the page.** All data lives in a Supabase project
  (Postgres + auth) and is only visible after signing in with an email that is
  on the team allowlist. The page itself contains no data, which is why the
  repo can be public.
- **No build step.** Plain HTML, CSS, and JavaScript. Edit a file, push, done.
  - `index.html` - static shell (auth screen, sidebar, main area)
  - `app.js` - all logic. The Supabase URL and publishable key are the two
    constants at the top.
  - `styles.css` - all styling
  - `vendor/` - supabase-js and JSZip, vendored so nothing loads from a CDN
  - `template_v5.xlsx` - the data-less Excel workbook used by Export to Excel
- **Export to Excel** downloads the whole database as the team's standard
  workbook (dashboard, formulas). It works by injecting the live
  data into `template_v5.xlsx` in the browser, so the download is exactly the
  same workbook the team used before this app existed. The template is
  generated by `../build_v5.py --template` in the parent project.

## What the app holds

- **Builders**: concessions, allowed uses, special process, CC rules, Dropbox
  link, and the people who work that builder. A builder's people are listed at
  the top of its page, with "+ Add person" right there.
- **Title companies**: team email, office phone and address, notes, plus up to
  six people each (escrow agent, assistant, closer, whoever else). Add them
  from the company's page. The limit is `MAX_TITLE_CONTACTS` at the top of
  `app.js`; raising it also means widening the Dashboard in `build_v5.py`.
- **Contacts**: standalone people who are not tied to one builder. Name,
  company or role, two phone numbers, two emails, and notes.

## Team access

Sign-ins are individual email + password accounts (Supabase auth). Access is
controlled by the team list inside the app (Team button, admins only), with
three levels enforced by row level security in the database:

- **read**: view everything and export to Excel, no editing
- **write**: read plus create/edit/delete builders, people, title companies,
  and contacts
- **admin**: write plus manage the team list and the contact role list

Adding a teammate:

1. An admin adds their email under Team and picks a level.
2. They open the app and choose "Create an account" with that exact email.

Removing an email immediately cuts off that person's access. The database
refuses to remove or demote the last remaining admin, so the team can never
lock itself out.

## Hosting and backend

- Frontend: GitHub Pages from this repo (main branch, root), owned by the
  TruRateLending GitHub account.
- Backend: Supabase project (free tier). Tables: `builders`, `contacts`,
  `title_companies`, `title_contacts`, `general_contacts`, `roles`,
  `allowed_users`. Row level security allows access only to signed-in users
  whose email is in `allowed_users`.
- The publishable key in `app.js` is safe to expose; row level security is
  what protects the data.
- A scheduled GitHub Action (`.github/workflows/keep-alive.yml`) pings the
  database twice a week so Supabase's free tier never pauses the project
  for inactivity. It also re-enables its own schedule so GitHub does not
  switch it off after 60 days without commits. If Supabase ever emails
  about an upcoming pause anyway, check the repo's Actions tab and make
  sure the "Keep Supabase awake" runs are green.

## Maintenance notes

- Roles in the person form are editable in the app (Edit the role list, from
  the Add person form). No code needed. Title contact roles are free text with
  a few suggestions, so a new one never needs a code change.
- Renaming builders and title companies is always safe: records are linked by
  id, not by name.
- Adding a brand-new structured field (a new column) is the one thing that
  needs a code change: add the column in Supabase, then add a matching form
  field in `app.js` and, if it should appear in the Excel export, a column
  mapping in `exportExcel()` plus a matching column in `build_v5.py`.
