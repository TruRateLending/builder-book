# Builder Book

A small team web app for tracking home builders: contacts, title companies and
escrow teams, concession rules, special processes, CC rules, and Dropbox links.
Built for a mortgage loan processing team.

Live app: https://truratelending.github.io/builder-book/

## How it works

- **This repo is just the page.** All data lives in a Supabase project
  (Postgres + auth) and is only visible after signing in with an email that is
  on the team allowlist. The page itself contains no data, which is why the
  repo can be public.
- **No build step.** Plain HTML, CSS, and JavaScript. Edit a file, push, done.
  - `index.html` - static shell (auth screen, sidebar, main area)
  - `app.js` - all logic. The Supabase URL and publishable key are the two
    constants at the top.
  - `styles.css` - all styling
  - `vendor/` - supabase-js and JSZip, vendored so nothing loads from a CDN
  - `template_v5.xlsx` - the data-less Excel workbook used by Export to Excel
- **Export to Excel** downloads the whole database as the team's standard
  workbook (dashboard, gap report, formulas). It works by injecting the live
  data into `template_v5.xlsx` in the browser, so the download is exactly the
  same workbook the team used before this app existed. The template is
  generated by `../build_v5.py --template` in the parent project.

## Team access

Sign-ins are individual email + password accounts (Supabase auth). Access is
controlled by the team list inside the app (Team button, admins only), with
three levels enforced by row level security in the database:

- **read**: view everything and export to Excel, no editing
- **write**: read plus create/edit/delete builders, people, and title companies
- **admin**: write plus manage the team list and the contact role list

Adding a teammate:

1. An admin adds their email under Team and picks a level.
2. They open the app and choose "Create an account" with that exact email.

Removing an email immediately cuts off that person's access. The database
refuses to remove or demote the last remaining admin, so the team can never
lock itself out.

## Hosting and backend

- Frontend: GitHub Pages from this repo (main branch, root), owned by the
  TruRateLending GitHub account.
- Backend: Supabase project `builder-book` (free tier). Tables: `builders`,
  `contacts`, `title_companies`, `roles`, `allowed_users`. Row level security
  allows access only to signed-in users whose email is in `allowed_users`.
- The publishable key in `app.js` is safe to expose; row level security is
  what protects the data.

## Maintenance notes

- Roles in the contact form are editable in the app (Edit the role list, from
  the Add person form). No code needed.
- Renaming builders and title companies is always safe: records are linked by
  id, not by name.
- Adding a brand-new structured field (a new column) is the one thing that
  needs a code change: add the column in Supabase, then add a matching form
  field in `app.js` and, if it should appear in the Excel export, a column
  mapping in `exportExcel()`.
